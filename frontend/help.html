Tesla Webmap の使い方

iPhoneの現在地と経由地を、テスラのブラウザへ共有するアプリです。4桁コードとiPhoneの接続許可で使い始められます。

通常のWebナビと、Tesla標準ナビへの送信は別の機能です。標準ナビへの送信には、Tesla APIの接続設定が必要です。

初期設定4桁で接続目的地と経由地ルートと音声Teslaへ送信終了する困ったとき更新と公開

1 初期設定

  1. iPhoneのSafariでアプリを開き、役割を「iPhone：現在地を送る」にします。
  2. 「中継サーバーの公開URL」に https://tesla-webmap.onrender.com を入力します。ハイフン「-」を使い、末尾に /health を付けません。
  3. 「設定を保存」を押します。
  4. 停車中のテスラで同じアプリを開き、役割を「テスラ：地図を見る」にして、同じ中継URLを保存します。

現在のアプリURLは https://ducat595.github.io/tesla_webmap/frontend/ です。独自の中継サーバーへ変更した場合は、両端末を同じURLに設定してください。

Google APIキーは任意です。未設定でもOpenStreetMapの地図と試験用のルート検索で動作確認できます。Google地図を使う場合は設定欄でキーを保存し、ページを再読み込みします。

2 4桁コードで接続する

  1. iPhoneで「共有を開始」を押し、Safariの位置情報を許可します。
  2. iPhoneに表示された4桁の数字をテスラの接続コード欄へ入力して「接続」を押します。先頭の0も入力します。
  3. テスラに表示される確認番号と、iPhoneの接続要求の確認番号が同じか見ます。
  4. 一致していれば、iPhoneで「接続を許可」を押します。確認番号を入力し直す必要はありません。
  5. テスラで現在地のマーカーと受信時刻が更新されることを確認します。

身に覚えのない要求は「拒否」を押してください。4桁を知っているだけでは位置を閲覧できません。初回の所有者登録を済ませた場合、接続許可によってTeslaナビへの送信権限も引き継ぎます。

3 目的地と経由地を設定する

目的地だけの場合

  1. iPhoneの「目的地を設定」で施設名や住所を入力し、「検索」を押します。
  2. 結果を選び、「経由地・目的地を画面へ共有」を押します。
  3. 両端末の「共有済みの通過順」とルートを確認します。

途中に寄る場所を追加する場合

  1. 寄りたい場所を検索して選び、「選択した場所を経由地に追加」を押します。
  2. 必要な場所を繰り返し追加します。経由地は最大8件です。
  3. 経由地一覧の↑・↓で順序を変え、不要な場所は「削除」します。
  4. 最後に最終目的地を検索して選びます。
  5. 「経由地・目的地を画面へ共有」を押して確定します。

経由地を追加・並べ替えただけでは車載側へ反映されません。共有ボタンを押してください。目的地は最後に通る場所です。経由順は自動で最適化せず、一覧の順を使います。

場所の指定は「地図をタップして指定」や、35.6812,139.7671 のような緯度・経度の入力でもできます。Googleマップアプリで追加した経由地を自動取り込みする機能はありません。

4 ルート表示と音声ナビを使う

  1. 現在地と共有した目的地がそろうと、各画面でルートを検索します。
  2. 音声を出す端末で「音声を有効にする・テスト」を押し、聞こえるか確認します。
  3. 同じ端末で「ナビ開始」を押します。
  4. 次に曲がる地点、そこまでの距離、残りの概算距離・時間が表示されます。

音声を両端末で有効にすると二重に案内します。車載ブラウザで音声が出ない場合は、iPhone側で有効にしてください。車のスピーカーへの出力はオーディオ設定と端末の対応によります。

iPhoneのSafariは表示したまま使います。画面ロック・別アプリへの切替・ヘルプの別タブ表示で位置更新が止まる場合があります。受信から15秒以上古い位置や精度の低い位置では案内を一時停止します。通信や位置取得が回復すると、新しい位置で案内を更新します。

本版のナビは試験版です。渋滞・最新の通行規制・充電計画は考慮しません。設定と初回確認は停車中に行ってください。

5 Tesla標準ナビへ送信する

この機能は、Webの位置共有が成功しただけでは使えません。Tesla開発者登録、所有者OAuth認証、車両の仮想キー、経由地コマンド対応の署名プロキシの設定が必要です。配布ZIPの TESLA_SETUP.md に準備を記載しています。

所有者登録はiPhoneで初回だけ

  1. iPhoneで「初回のみ：iPhoneを所有者端末として登録」を開きます。
  2. Renderの TESLA_OWNER_SECRET に設定したキーを一度入力し、「このiPhoneを登録」を押します。
  3. 登録後30日間、同じSafariではキーを再入力しません。許可した車載ブラウザへの転記も不要です。

Safariのデータ消去、プライベートモード、30日の期限切れ、所有者キー変更時は再登録が必要です。全端末を解除するにはRenderの所有者キーを変更して再デプロイします。

地点一覧を送信する

  1. 各経由地と目的地のGoogle Place IDが設定されていることを確認します。Google地図で検索した地点は自動で保持します。
  2. 地点一覧を画面へ共有し、通過順を確認します。
  3. 「共有済みの地点一覧をTeslaへ送信」を押します。ナビ開始と同時に送るなら「ナビ開始時にTesla標準ナビにも送信」にチェックします。
  4. 受付成功の表示後、Tesla標準ナビで経由地と目的地の順序を確認します。

OSM検索・地図タップ・座標入力の地点には、別途Google Place IDが必要です。GoogleのPlace ID確認ツールを使えます。

Teslaへ送るのは地点と順序です。道路のルートはTeslaが再計算し、Web地図と同じ道を通るとは限りません。送信結果が不明な場合は自動再送せず、車載ナビを先に確認してください。

6 使用を終了する

iPhoneで「共有を停止・削除」を押します。位置情報、経由地、目的地、接続許可を削除し、車載側も接続できなくなります。タブを閉じるだけでは、サーバーの情報は直ちに消えません。

「削除に失敗しました」と表示されたら通信を確認し、停止ボタンで再試行してください。位置の送信は停止しますが、削除できなかった情報はセッション期限まで残る場合があります。

7 困ったとき

「Load failed」やサーバーへ接続できない

中継URLが https://tesla-webmap.onrender.com になっているか確認します。ハイフンとアンダースコアを間違えないでください。

稼働確認ページで {"ok": true} が出るか確認します。Renderの ALLOWED_ORIGINS は https://ducat595.github.io で、リポジトリ名や末尾のスラッシュは付けません。

4桁を入力しても地図が表示されない

iPhoneの接続要求で「接続を許可」を押してください。許可待ちは2分間です。両端末の表示バージョンがv6かも確認します。コードの新規受付は10分間で、Render再デプロイ後は新しいコードが必要です。

「位置情報はまだありません」や更新停止になる

iPhoneのSafariを表示し、位置情報を許可してください。座標欄だけでなく、その上の接続状態メッセージも確認します。画面ロックや別アプリへの切替は更新停止の原因になります。

地図だけ出ない、Googleの認証が失敗する

ネット接続と外部地図サービスの読み込みを確認します。Googleを使う場合はMaps JavaScript API・Routes API・Geocoding API、課金設定、公開URLとAPIのキー制限を確認してください。キーを空欄で保存して再読み込みすると、OSMで動作確認できます。

経由地を編集したのに反映されない

「経由地・目的地を画面へ共有」を押してください。共有済みの通過順が車載側にも表示されているか確認します。

Tesla送信が未設定、所有者確認が必要と表示される

標準ナビへの接続設定と初回のiPhone登録を確認します。認証トークン期限切れ、仮想キー未登録、プロキシの経由地コマンド未対応でも送信できません。Webのルート表示とは別の確認です。

所有者キーを毎回入力させられる

同じSafariを使い、プライベートモードやデータ消去を避けてください。中継URLを変えると別の登録になります。キー変更や30日の期限切れ後は再登録します。

音声が出ない

案内する端末で「音声を有効にする・テスト」を押し、端末や車の音量を確認します。車載ブラウザが非対応ならiPhone側で試してください。

8 公開と更新の手順

  1. GitHubの frontend と backend をフォルダ構成を保って配置します。フォルダの中身を全て同じ階層へまとめません。
  2. GitHub Pagesをmainブランチのrootで公開し、/frontend/ の画面を開きます。
  3. RenderのBuild Commandは python -m compileall backend、Start Commandは python backend/server.py にします。
  4. Health Check Pathは /health。環境変数と公開URLを確認します。
  5. 更新後は再デプロイし、両端末を再読み込みします。右上の「かんたん接続 v6」を確認してください。

詳細な機能、API、保存期間、判定条件、検証範囲は仕様書に記載しています。
